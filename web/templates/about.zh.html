判定规则

什么算"承诺"

论文给出了自己的 GitHub 仓库链接，或者写了"代码将会发布"，就算作承诺。我们看两个地方：

  • arXiv 接口返回的摘要和备注。
  • 论文正文（arXiv 的 HTML 版）。正文里的链接，只有它所在的那句话是在说作者自己的工作时才算，比如 "Our code is available at …"、"Code: …"。参考文献里的链接、指向别人代码的链接一律不算。

只收录 arXiv 备注里写明被会议录用的论文（例如 "Accepted at ICLR 2025"），workshop 论文和"在审"的论文不收录。

仓库状态怎么判定

对仓库的默认分支做一次浅克隆，看最新一次提交里有哪些文件。

状态规则
已开源代码文件（.py、.ipynb、.cpp、.cu、.js 等）合计不少于 5 KB。
只有少量代码有代码文件，但合计不到 5 KB。
只有数据没有代码文件，但数据或模型文件（.json、.csv、.pt、.safetensors 等）不少于 100 KB。基准测试类论文常见。
仓库为空没有代码，也没有像样的数据，只有 README、许可证或图片。
仓库已失效仓库不存在或被设为私有。
arXiv 版本里没有仓库arXiv 版本写了代码将会发布，但没有给出仓库链接，或者只给了匿名评审用的链接（anonymous.4open.science）。放在 GitHub 以外的代码可能被漏掉，欢迎告诉我们。

"承诺 N 天"从两个日期中较晚的那天算起：论文在 arXiv 上首次公开的日期，以及会议开幕的日期。

什么算"未兑现"

只算三种状态：仓库为空、只有少量代码、仓库已失效。"只有数据"不算，因为基准测试类论文可能本来就只需要公开数据。"arXiv 版本里没有仓库"也不算。原因是 arXiv 上的最新版本有时仍是双盲评审期间的版本，作者可能把代码发布在项目主页或其他地方，只是没有更新 arXiv。

作者清单（补充信息）

很多 README 里有这样的清单：“- [x] Release inference code / - [ ] Release training code”。对已开源的论文，网站会额外列出作者自己清单上还没勾的项。这只是补充信息，不计入“没兑现”。

为了不冤枉作者，只算明确的发布承诺：以 Release、Open-source、Upload、Publish 开头，或者是“Training code”“Checkpoints”这类短项，而且说的是代码、权重或数据。扩展计划（“更多数据集”“新版本”“支持……”）、删除线划掉的项、关于论文本身的项都不算。清单上训练或推理代码没勾、但仓库里已经有对应文件（比如 train.py）的，当作作者忘了勾。网站只照原文引用清单，不做进一步的判断。

我们不做什么

  • 不显示作者名字，也不做评价。仓库为空可能有正当原因，我们只报告仓库里有什么。
  • 只检查默认分支。如果代码在其他分支或者其他网站上，请告诉我们。

局限

  • 只覆盖 arXiv 备注里写了会议名的论文，大约是录用论文的四成多。
  • 正文分析依赖 arXiv 的 HTML 版，有些论文没有 HTML 版。
